> **อัปเดตล่าสุด**: 29 มีนาคม 2026

## 📋 สรุปบริหารระดับสูง (Executive Summary)

**Culinary Crafts** คือตัวช่วยทำอาหารที่ใช้ AI พูดคุยแบบอัตโนมัติ เพื่อช่วยให้ผู้คนค้นหาสูตรอาหารที่ปรับแต่งตามความต้องการ โดยอยู่บนพื้นฐานของวัตถุดิบที่มีอยู่ ข้อจำกัดด้านโภชนาการ และการแพ้อาหาร โดยใช้โมเดล Gemini Vision และ Language Model ของ Google ให้วิเคราะห์ภาพถ่ายวัตถุดิบ และสร้างคำแนะนำเมนูอาหารตามความต้องการแบบเรียลไทม์

### ประเด็นนวัตกรรมหลัก

ต่างจากแอปพลิเคชันสูตรอาหารทั่วไป Culinary Crafts จะ **เรียนรู้** ความต้องการของคุณ (การแพ้อาหาร สไตล์อาหารที่ชอบ ระดับทักษะ) และให้คำแนะนำจากแหล่งที่มาที่ตรวจสอบแล้ว—ซึ่งจะขจัดปัญหา AI ที่สร้างข้อมูลเท็จ และลดความเสี่ยงด้านความปลอดภัยในอาหาร

## 🎯 ปัญหาที่ต้องการแก้ไข (Problem Statement)

### ความท้าทายในปัจจุบัน

1. **ความหนักใจในการตัดสินใจ** - ผู้ใช้งานเสียเวลาคิดว่าจะทำอะไรจากวัตถุดิบที่มีจำกัด
2. **การสูญเสียอาหาร** - วัตถุดิบเน่าเสียก่อนนำมาใช้งานได้อย่างมีประสิทธิภาพ
3. **AI สร้างข้อมูลเท็จ** - แอปพลิเคชันสูตรอาหารทั่วไปสร้างสูตรที่ไม่มีอยู่จริง หรือแนะนำวัตถุดิบที่ผู้ใช้ไม่มี
4. **ข้อเสนอแบบเดียว** - ไม่คำนึงถึงการแพ้อาหารและความชอบส่วนตัวของผู้ใช้
5. **การพิมพ์วัตถุดิบที่ยุ่งยาก** - การพิมพ์รายการวัตถุดิบนั้นเสียเวลาและเสี่ยงต่อข้อผิดพลาด

### กลุ่มผู้ใช้เป้าหมาย

- 👩‍🍳 **คนทำอาหารที่บ้าน** (อายุ 25-55 ปี) ที่ต้องการวางแผนอาหารที่เร็วขึ้น
- 👨‍⚕️ **ผู้ที่มีสติในเรื่องสุขภาพ** ที่มีข้อจำกัดทางโภชนาการ (เจ, ไม่มีกลูเตน เป็นต้น)
- 🥜 **คนที่มีการแพ้อาหาร** ที่ต้องการการกรองคำแนะนำที่ปลอดภัย
- 📱 **ผู้ใช้มือถือเป็นหลัก** ที่ชอบใช้อินเทอร์เฟซแบบภาพ

## ✨ วิธีแก้ปัญหาที่เสนอ (Proposed Solution)

### Culinary Crafts คืออะไร?

**ตัวช่วยทำอาหารแบบมัลติโมดัล** ที่:

1. **รับอินพุตแบบมัลติโมดัล**
   - ข้อความ: "ฉันจะทำอะไรได้จากพาสต้าและมะเขือเทศ?"
   - ภาพ: รูปถ่ายตู้เย็นหรือวัตถุดิบบนเคาน์เตอร์
   - แบบผสม: ภาพ + บริบท ("ทำแบบเจได้ไหม?")

2. **วิเคราะห์ด้วย AI**
   - ตรวจจับวัตถุดิบจากภาพโดยใช้ Gemini 1.5 Pro Vision
   - ระบุสารอาหารที่อาจทำให้แพ้และข้อจำกัด
   - กรองสูตรตามความต้องการของผู้ใช้
   - จัดเรียงตามความสะดวกและระดับทักษะ

3. **ให้คำแนะนำที่ปลอดภัย**
   - แนะนำเฉพาะสูตรที่ผู้ใช้สามารถทำได้อย่างปลอดภัย
   - อ้างอิงแหล่งที่มา (คำแนะนำบนพื้นฐาน)
   - เก็บความต้องการไว้เพื่อให้มีการปรับแต่งเมื่อเวลาผ่านไป
   - อธิบายการแทนที่วัตถุดิบ

4. **จำข้อมูลผู้ใช้**
   - เก็บความต้องการด้านโภชนาการ (การแพ้อาหาร ข้อจำกัด)
   - เรียนรู้ความชอบด้านวัฒนธรรมอาหาร
   - ติดตามสูตรโปรด
   - ให้คำแนะนำโดยอิงจากประวัติ

## 📊 คุณลักษณะหลัก (Key Features)

### 1. **การค้นหาสูตรแบบมัลติโมดัล** (Multimodal Recipe Discovery)

#### ค้นหาโดยใช้ข้อความ

```
ผู้ใช้: "ฉันมีพาสต้า มะเขือเทศ และกระเทียม"
AI: "ยอดเยี่ยม! คุณสามารถทำได้:
    1. Pasta al Pomodoro (15 นาที)
    2. Aglio e Olio (10 นาที)
    3. Pasta Agliata (5 นาที)"
```

#### ค้นหาโดยใช้ภาพ

```
ผู้ใช้: [ถ่ายรูปตู้เย็น]
AI: "ฉันเห็น: มะเขือเทศ (3) โหระพา มอซซาเรลลา น้ำมันมะกอก
    คำแนะนำ:
    1. Caprese Salad (สดชื่นและเร็ว)
    2. Margherita Pizza (ต้องใช้แป้ง)
    3. Tomato Basil Soup (ถ้าคุณมีน้ำซุป)"
```

### 2. **ความต้องการส่วนตัว** (Personalized Preferences)

```
โปรไฟล์ผู้ใช้:
├─ การแพ้อาหาร: ถั่วลิสง กุ้ง ซอยซ๊อส
├─ โภชนาการ: เจ, ไม่มีกลูเตน
├─ อาหารที่ชอบ: อิตาลี, ไทย, เมดิเตอร์เรเนียน
├─ วัตถุดิบที่หลีกเลี่ยง: ผักชี, มะกอก
└─ ระดับทักษะ: ระดับกลาง (สูตรที่ใช้เวลา 15-40 นาที)

AI จะกรองสูตรทั้งหมดผ่านข้อจำกัดเหล่านี้
→ ไม่มีคำแนะนำที่ไม่ปลอดภัย
→ ความพึงพอใจและความเชื่อถือที่สูงขึ้น
```

### 3. **ประวัติการสนทนา** (Conversation History)

```
บันทึกการค้นหาและผลลัพธ์ทั้งหมด:
├─ วัตถุดิบที่ใช้
├─ สูตรที่แนะนำ
├─ สูตรที่ผู้ใช้คลิก
└─ ข้อเสนอของผู้ใช้ (มีประโยชน์/ไม่มีประโยชน์)

ใช้สำหรับ:
└─ การปรับแต่งเมื่อเวลาผ่านไป
└─ คำแนะนำที่ได้รับความนิยม
└─ งานวิจัยและข้อเสนอของผู้ใช้
```

### 4. **คำแนะนำที่ปลอดภัย** (Safe Recommendations)

```
สูตรทุกฉบับรวมถึง:
├─ การอ้างอิงแหล่งที่มา (บนพื้นฐาน)
├─ การตรวจสอบความเข้ากันได้ของการแพ้อาหาร
├─ คำแนะนำในการแทนที่วัตถุดิบ
├─ ข้อมูลโภชนาการ (ถ้ามี)
├─ เวลาเตรียมและปรุง
├─ ระดับทักษะที่จำเป็น
└─ บทวิจารณ์ของผู้ใช้ (อัตราดาว)
```

## 🔒 ความปลอดภัยและความเป็นส่วนตัว (Security & Privacy)

### การยืนยันตัวตนและสิทธิอำนาจ

- Google OAuth 2.0 (ไม่ต้องเก็บรหัสผ่าน)
- JWT tokens (อายุ 24 ชั่วโมง)
- Secure HTTP-only cookies
- CSRF protection

### การป้องกันข้อมูล

- การเข้ารหัสแบบปลายต่อปลายสำหรับการเรียก API (HTTPS/TLS 1.3)
- การเข้ารหัสฐานข้อมูลในขณะหยุดนิ่ง
- ไม่มีข้อมูลที่ละเอียดอ่อนในบันทึก
- ปฏিบัติตาม GDPR (ลบข้อมูลตามคำขอ)

### มาตรการป้องกันความปลอดภัย

- การทำให้ข้อมูลใช้งานได้ (ป้องกันการฉีด SQL)
- อัตราจำกัด (10 ขอ/นาที ต่อผู้ใช้)
- การตรวจสอบประเภทไฟล์ (ภาพ)
- ตัวกรองความปลอดภัย Gemini API

### การพัฒนาในท้องถิ่น

```bash
# รันบริการใน Docker
docker-compose -f docker-compose.services.yml up

# รันโค้ดในท้องถิ่น (hot reload)
cd backend && uvicorn app.main:app --reload
cd frontend && npm run dev
```

### สภาแวดล้อมการผ่าการทดสอบ

```
- ทดสอบการเปลี่ยนแปลงทั้งหมดก่อนเปิดตัว
- ใช้ฐานข้อมูลการผ่าการทดสอบ
- ทดสอบด้วย Gemini API ที่แท้จริง (โควตาที่ จำกัด)
- ตรวจสอบการไหลของผู้ใช้ด้วยผู้ทดสอบ Beta
```
